WoodFlow

Веб-приложение для складского учёта пиломатериалов: от регистрации пачки на складе до формирования партии, оформления отгрузки и выгрузки накладной в Excel.

WoodFlow хранит характеристики продукции, рассчитывает объёмы и вес, отслеживает бронирования и предоставляет сводные показатели по складу и отправкам.

## Возможности

- **Складской учёт:** добавление и редактирование пачек, хранение размеров, сорта, количества досок, слоёв и примечаний; фильтрация по ширине и статусу.
- **Расчёты:** фактические и номинальные объёмы и веса для покупателя и таможни.
- **Бронирование партий:** реквизиты покупателя, договор, цена за м³, добавление и исключение пачек, отмена брони с возвратом продукции на склад.
- **Оформление отгрузок:** логистическая компания, номера автомобиля, прицепа, контейнера и пломбы.
- **Архив:** просмотр отправок и подробностей каждой отгруженной партии.
- **Excel-документы:** генерация накладной `.xlsx` по готовому шаблону.
- **Панель администратора:** остатки, активные бронирования, показатели выручки, графики объёмов отправок и последние отгрузки.
- **Управление пользователями:** создание учётных записей, назначение роли администратора, активация и деактивация пользователей.

## Технологии

| Компонент | Технологии |
| --- | --- |
| Серверная часть | Python, Flask |
| База данных и ORM | SQLite, SQLAlchemy, Flask-SQLAlchemy |
| Авторизация и формы | Flask-Login, Werkzeug, Flask-WTF |
| Интерфейс | Jinja2, HTML, CSS, JavaScript, Bootstrap 5, Bootstrap Icons |
| Графики | Chart.js |
| Excel | openpyxl |

Интерфейс формируется сервером с помощью Jinja2. Данные для графиков передаются через JSON-маршруты.

## Основной сценарий работы

1. Сотрудник добавляет пачки пиломатериалов на склад и указывает их характеристики.
2. Приложение рассчитывает объёмы и вес.
3. Сотрудник создаёт бронирование для покупателя, указывает договор и цену за м³.
4. Доступные пачки включаются в партию и получают статус «забронирована».
5. При отправке сотрудник заполняет сведения о транспорте и логистической компании.
6. Партия и её пачки переходят в статус «отправлена», отгрузка появляется в архиве.
7. Накладная скачивается в формате Excel.

При отмене активного бронирования связанные пачки снова становятся доступными на складе.

## Локальный запуск

### Требования

- Python 3.11 или новее: код использует `datetime.UTC`.
- Git и pip.
- Доступ к интернету для установки зависимостей и загрузки Bootstrap, иконок и Chart.js с CDN.

### 1. Клонирование

```bash
git clone --branch develop https://github.com/platonpotemkin51-source/WoodFlow.git
cd WoodFlow
```

### 2. Виртуальное окружение

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux / macOS:

```bash
source .venv/bin/activate
```

### 3. Зависимости

```bash
python -m pip install -r requirements.txt
python -m pip install Flask-SQLAlchemy Flask-WTF tzdata
```

В текущей ветке `develop` пакеты Flask-SQLAlchemy и Flask-WTF импортируются приложением, но отсутствуют в `requirements.txt`, поэтому устанавливаются отдельно. `tzdata` обеспечивает доступ к часовому поясу `Europe/Moscow` в системах без базы часовых поясов, в том числе Windows.

### 4. Секретный ключ

Создайте случайный ключ:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Задайте полученное значение в текущем терминале.

Windows PowerShell:

```powershell
$env:SECRET_KEY = "вставьте-сгенерированный-ключ"
```

Linux / macOS:

```bash
export SECRET_KEY="вставьте-сгенерированный-ключ"
```

Приложение читает ключ из переменной окружения. Автоматическая загрузка `.env` в коде не настроена.

### 5. Запуск

Выполните из корня проекта:

```bash
python app.py
```

Откройте [http://localhost:5000](http://localhost:5000).

При инициализации приложение создаёт отсутствующие таблицы. Если в базе нет администратора, создаётся начальная учётная запись:

- Логин: `admin`
- Пароль: `admin123`

Репозиторий уже содержит `woodflow.db`. Если в этой базе есть администратор, новая учётная запись не создаётся и указанные данные входа могут не подойти.

Для отдельного запуска с чистой базой предварительно сохраните копию `woodflow.db` и переместите исходный файл из каталога проекта. При следующем запуске приложение создаст новую базу.

## Расчёты

Размеры в расчётах задаются в миллиметрах, объёмы — в м³, вес — в килограммах.

При добавлении пачки используются следующие правила:

```text
Номинальная ширина доски = фактическая ширина − 3 мм
Номинальная толщина доски = фактическая толщина − 3 мм

Объём досок = ширина × толщина × длина × количество × 10⁻⁹
Фактический объём пачки для таможни = ширина пачки × высота пачки × длина пачки × 10⁻⁹
Номинальный объём для таможни = фактический объём пачки × 0,92

Вес = соответствующий объём × 630 кг/м³
Стоимость партии = суммарный номинальный объём для таможни × цена за м³
```

Для номинального и фактического объёма досок используются соответствующие размеры и длины. Коэффициент `0,92` и плотность `630 кг/м³` заданы в коде и не настраиваются через интерфейс. Это правила текущей реализации, которые следует сверять с требованиями конкретного производства.

## Структура проекта

```text
WoodFlow/
├── app.py                  # Маршруты, бизнес-логика, инициализация и запуск
├── config.py               # Настройки приложения
├── models.py               # User, WoodPack, Booking, Shipment
├── excel_utils.py          # Формирование Excel-накладных
├── requirements.txt        # Зависимости
├── woodflow.db             # База SQLite
├── templ_xlsx/
│   └── pok.xlsx            # Шаблон накладной
├── templates/              # HTML-шаблоны Jinja2
└── static/
    └── css/
        └── style.css       # Стили интерфейса
```

`User` хранит пользователей и роли, `WoodPack` — пачки пиломатериалов, `Booking` — партии и бронирования, `Shipment` — сведения об отправках. Бронирование объединяет пачки и связано с записью отгрузки.

## Настройки и файлы

| Параметр | Назначение |
| --- | --- |
| `SECRET_KEY` | Ключ сессий и CSRF; читается из переменной окружения |
| `SQLALCHEMY_DATABASE_URI` | Путь к SQLite; задаётся в `config.py` |
| `EXPORT_FOLDER` | Каталог `exports`, создаваемый при запуске `python app.py` |
| `templ_xlsx/pok.xlsx` | Шаблон Excel-накладной |

Excel-файл формируется в памяти и отдаётся браузеру для скачивания. Шаблон открывается по относительному пути, поэтому приложение нужно запускать из корня проекта.

## Состояние ветки develop

Инструкция подготовлена по исходному коду; запуск приложения в рамках подготовки README не проверялся.

Особенности текущей реализации:

- `requirements.txt` требует дополнения зависимостями, указанными в инструкции установки.
- `db.create_all()` создаёт отсутствующие таблицы, но не выполняет миграции существующей схемы.
- Сортировка склада по объёму обращается к отсутствующему полю `WoodPack.volume` и требует исправления.
- При повторном добавлении пачек в бронь `pack_count` записывает количество из последнего добавления, поэтому счётчик может расходиться с фактическим составом партии.
- В `excel_utils.py` итоговая строка веса использует показатель для таможни, а строки пачек — показатель для покупателя; перед использованием накладной необходимо согласовать расчёт итога.

При прямом запуске включён `debug=True`, сервер слушает `0.0.0.0:5000`. Для публикации приложения нужно отключить отладку, настроить WSGI-сервер, заменить начальные учётные данные и задать собственный `SECRET_KEY`. Маршрут `/api/last-shipments` сейчас доступен без авторизации; остальные JSON-маршруты статистики требуют входа, но не проверяют роль администратора.
